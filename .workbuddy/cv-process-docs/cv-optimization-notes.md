# CV 网页优化与中英双语实现说明

> 配套文件：`cv-generator.js`（核心函数）、`cv-en.html`（英文版）、`cv-zh.html`（中文版）。
> 本说明回答三件事：① 英文内容如何转化为中文；② 实现中较困难的前提条件；③ 你是否需要提前准备翻译资料 / 术语表。

---

## 一、本次设计优化（已对齐站点 `style-guide.txt`）

### 1. 网页外壳（cv-en.html / cv-zh.html）
- **配色仅用站点规定色板**：白 `#fff`、米色 `#fbfaf7`、墨 `#1b1b1b`、灰 `#6d6a63`、浅线 `#e3ded4`、深红 `#8c2f39`、深红悬停 `#6b2229`。**去掉了原先自创的 `#f4f4f4` 背景与 `#ddd` 分隔线**（二者不在站点色板内）。
- **字体**：沿用系统字体栈，不加载任何 Web 字体（与全站一致）。
- **行高 1.7**（指南正文标准）。
- **四段式页面结构**（指南强制）：① 顶部「← Back to About」深红返回链接；② 页头 `h1`（1.8em，墨色）+ 一行灰色副标题 + **2px 深红横线**收尾；③ 单列居中主内容（≤860px）；④ 页脚 `© 2026 ExtremalMath` + `Last updated Oct 17, 2026`。
- **两语言版本结构完全一致**，仅在文本与 `lang` 参数上不同。

### 2. 简历正片（打印 / PDF 内容）放大、加疏、强化层级
- 字号 **12px → 13.5px**；姓名 **22px → 28px**；板块标题 **12.5px → 15px**；
- 行高 **1.5 → 1.6**（取舍见下）；
- 板块间距 **16px → 26px**，条目间距 **7px → 11px**，页内边距 **26/30 → 34/40**，整体更"丰满"；
- 分组小标题（研究兴趣 / 技能 / 服务）用**深红 `#8c2f39`** 强调，建立清晰视觉层次；
- 保留你最初指定的"**黑框白底**"专业简历外观（`2px solid #000`），并新增 `break-inside:avoid`，避免打印分页切断条目。

> **关于行高的取舍**：指南正文行高为 1.7。但简历是横向 A4 打印件、版面高度有限；若严格用 1.7，在放大字号后会自然撑到 2 页。我取 **1.6** 作为"更丰满"与"尽量单页"的平衡，并允许内容偏多时自然分页（学术 CV 多页属正常）。如你要求严格 1.7，我可一键改回（`cv-generator.js` 内 `.cv-sheet` 的 `line-height` 改为 `1.7`，代价是更可能分页）。

## 二、英文 → 中文的转化方式

源站 `about.html` / `talks.html` 正文以**英文为主**。双语方案如下：

1. **英文版**：直接抓取源页 DOM 文本、原样呈现（`lang:'en'` 时翻译函数直接返回原文），保证与源站绝对同步、零翻译误差。
2. **中文版**：`cv-generator.js` 内置两层翻译——
   - **整句层 `ZH`**：键＝英文原文整句，值＝人工审定中文（精确、零歧义），优先使用；
   - **术语层 `TERMS`**：对未命中整句的英文自由文本，按"长词条优先"做子串中译（如 `Extremal Graph Theory → 极值图论`、`Third Prize → 三等奖`），覆盖未来可能新增的内容，避免整句回退英文。
   - 两层配合，既保证现有内容高质量中译，又让"可能用到的术语表"真正生效。
3. **标点归一化防漏译**：源页与词典的弯引号 `‘’ “”`、长破折号 `– —` 极易不一致，导致查表失败而漏译。故 `norm()` 统一归一为直引号与短横，并预构建 `ZHN` 索引，确保稳健匹配。
4. **回退机制**：词典未命中的新内容（例如你日后在 about 页新增的句子）**回退为英文原文**而非丢空——保证"不遗漏任何内容"，只是该句中英不完全一致。
5. **中文专有摘要**：`BIO_ZH` 单独手写克制的中文个人简介（源站 bio 是英文长句，不宜逐字机翻）。
6. **演讲双语**：`talks.html` 每条 talk 自带 `.zh` 中文标题，中文版优先用 `.zh`，英文版用原文。

## 三、实现中较困难的前提条件

1. **源页必须有稳定、规范的 CSS 选择器结构**。生成器依赖 `.hero-info h1`、`.timeline-item`、`.research-card`、`.award-list li`、`.skills-grid .skill-item`、`.exp-item`、`.talk` 等钩子抽取内容。一旦你改版 about / talks 页面的结构或类名，生成器需同步维护——这是"内容随源同步"的硬前提。
2. **同源部署 / 抓取可达性**。超链接触发走 `fetch`，须经 http(s)（GitHub Pages 或本地静态服务器）访问；直接双击本地文件会被浏览器协议拦截（前端已给出友好提示）。
3. **课程作业过滤依赖显式标签**。排除规则靠 `excludeTalkTypes`（如 `course talk`）与 `excludeKeywords`（homework / 课程作业 / Core Coursework 等）。若日后新增作品未带这些标签却属课程作业，需手动补关键词。
4. **横向 A4 版面的篇幅约束**。放大字号后内容可能跨 2 页；需靠 `break-inside:avoid` 与适度精简维持可读。
5. **字体渲染一致性**：中英文混排依赖系统中文字体（PingFang SC / Microsoft YaHei），不同 OS 预览略有差异，但打印 PDF 由浏览器统一栅格化，影响很小。

## 四、你是否需要提前准备翻译资料 / 术语表？

**不需要提前准备，但建议维护一份"受控术语表"。**

- 当前已能**自动工作**：英文版直取源；中文版靠内置词典 + 标点归一化 + 回退，已覆盖 about / talks 全部现有条目（此前 17 项断言验证全 PASS）。
- **唯一会"露英文"的情形**：你在 about / talks 新增了未收录进 `ZH` 词典的长句或专有名词。此时中文版会回退显示英文原文——不丢内容，但中英不完全一致。
- **建议做法**：若你计划持续扩充简历内容，最好在 `cv-generator.js` 的 `ZH` 对象里**增量补充**你审定过的中译（数学专有名词如 `Extremal Graph Theory → 极值图论` 已建好）。这与站点"文件命名 / 内容统一"的维护惯例一致。

换言之：术语表即 `cv-generator.js` 内的 **`ZH`（整句）＋ `TERMS`（术语）** 两层结构，由你按需增删即可，无需另起一份独立文档：
- 新增长句 / 简介 → 在 `ZH` 加「英文整句 → 中文」；
- 新增专有名词 / 惯用短语 → 在 `TERMS` 加「英文 → 中文」一对（长词在前、自动排序）。

两套都改在源文件同一处，维护成本极低。
