Lean 4 Setup & Download Guide

Windows 环境下极简安装与避坑：国内镜像 + 手动配置变量。

Lean 4 的运行依赖于 VS Code 插件（前端界面） 和 Lean 工具链（底层编译器）。 由于官方服务器在国外，国内直接下载极易遇到网络超时问题。本攻略采用国内镜像 + 手动配置环境变量 + 复用本机已编译 mathlib 的方式，确保安装顺利。

〇、核心认知（先看这几点，少走 90% 弯路）

  • 本地有 mathlib 源码 ≠ 依赖齐全。mathlib 会拖着一整条依赖链，缺一不可。
  • .olean 和编译器版本严格一对一绑定。换 toolchain = 旧产物全废，必须重编。
  • 无代理时，lake exe cache get（走 curl 连 Azure / Cloudflare）和 git clone GitHub 基本都连不上；ghproxy 一类镜像只对 git clone 有效、对缓存下载无效，且自身也不稳定。
  • 最稳的路不是"下载"，而是"复用本机已编译好的 mathlib"。
  • 不要同时开第二个窗口跑 lake exe cache get：并发写同一个 .lake 会弄坏产物（典型症状：报 failed to open ... .olean: 2 缺文件）。

一、前置准备

  • 安装 VS Code：确保已安装最新版。
  • 安装 Lean 4 扩展：Lean 4（发布者为 leanprover），点击安装。
    注：此时先不要急着打开 .lean 文件，否则它会自动触发极慢的官方下载。

二、版本选择

  • 推荐使用一个已发布但足够稳定的版本（例如 leanprover/lean4:vX.Y.Z）；候选版（rc）日常学习也够用。
  • 选定后锁死版本，别频繁更新——.olean 与编译器绑定，更新往往要连带重编 mathlib，成本很高。
  • 各项目的 lean-toolchain 内容必须逐字一致，否则编译产物无法互相复用。

三、第一步：配置系统环境变量（核心避坑）

为了防止 Lean 霸占 C 盘空间，并确保系统能识别到相关命令，我们需要提前配置环境变量：

  1. 按 Win 键，搜索并打开 “编辑系统环境变量”。
  2. 点击 “环境变量”。
  3. 新建 ELAN_HOME 变量（用户变量）： 变量名：ELAN_HOME，变量值：你希望安装的路径，例如 D:\Lean\elan（路径不要有中文和空格）。
  4. 修改 Path 变量（用户变量）： 找到 Path，双击编辑 → 新建 → 填入 %ELAN_HOME%\bin → 一路确定保存。

四、第二步：通过镜像手动安装 Elan

因为官方下载地址在国内经常报 Timeout 错误，我们直接使用上海交大（SJTUG）的镜像：

  1. 打开浏览器，访问镜像站列表：https://mirror.sjtu.edu.cn/elan/elan/releases/download/?mirror_intel_list
  2. 找到最新的 Windows 版本压缩包，例如 elan-x86_64-pc-windows-msvc.zip，下载并解压。
  3. 解压后得到一个 elan-init.exe。
  4. 打开一个全新的 CMD 或 PowerShell 窗口（必须新开，才能读取刚才设的变量）。
  5. 运行 elan-init.exe，它会自动将 Elan 安装到刚才设置的 ELAN_HOME 目录。

五、第三步：使用镜像安装 Lean 工具链

Elan 装好后，临时指定镜像源再下载 Lean 编译器：

  1. 打开一个新的 PowerShell 窗口。
  2. 执行 $env:ELAN_DIST_SERVER = "https://mirror.sjtu.edu.cn/elan" （CMD 为 set ELAN_DIST_SERVER=https://mirror.sjtu.edu.cn/elan）。
  3. 安装 Lean 稳定版：
    elan toolchain install leanprover/lean4:stable
  4. 将其设为默认版本：
    elan default leanprover/lean4:stable
  5. 验证安装： 
    lean --version
    输出 Lean (version 4.x.x...) 即说明编译器已就位。

六、项目公用环境：path 复用（推荐路线）

最稳的路是"复用本机已编译好的 mathlib"，核心是走本地路径，不跟下载源较劲。
  1. 安装 elan + 工具链（约 3 GB）：
    curl https://elan.lean-lang.org/elan-init.sh -sSf | sh
    这一步已在第三章完成，可跳过。
  2. 新建项目：
    lake init myproject math
cd <你的项目目录>
  3. 对齐 toolchain（关键）：把本项目 lean-toolchain 改成与"已编译好的那份 mathlib"完全相同。
  4. 在 lakefile.toml 末尾加 path 依赖：
    [[require]]
name = "mathlib"
path = "<已编译好的 mathlib 包根目录，用正斜杠>"
    path 要指到含 lakefile 的 mathlib 包根目录，不是更内层的 Mathlib 子目录。
  5. 构建 + 验证：
    lake build
    新建测试文件：
    import Mathlib
example : 2 + 2 = 4 := by norm_num   -- 显示 No goals 即成功

七、备用方案：自己编译 mathlib

如果必须自己编译 mathlib（无缓存兜底）：

cd <mathlib 源码目录>
echo "leanprover/lean4:vX.Y.Z" > lean-toolchain
lake build          # 全量编译较慢，约上万 job
  • 中断了直接重跑 lake build：Lake 靠 trace 做增量编译，自动从断点续编，进度不丢；千万别 lake clean（会清空全部产物、从零重编）。
  • 内存吃紧被杀就降并行：
    lake build -j 2

八、在 VS Code 中创建并测试项目

⚠️ 避坑警告：绝对不要在 VS Code 中直接打开一个孤立的 .lean 文件！插件需要通过项目根目录下的 lakefile 和 lean-toolchain 来识别环境。
  1. 在命令行中，进入你存放代码的目录，创建一个新项目：
    lake new myproject
cd myproject
  2. 在当前项目文件夹下，启动 VS Code：
    code .
  3. 在 VS Code 左侧资源管理器中，双击打开自带的 Main.lean 文件，输入以下测试代码并保存：
    #eval 1 + 1
def factorial : Nat → Nat
  | 0 => 1
  | n + 1 => (n + 1) * factorial n
#eval factorial 5
example (a b : Nat) : a + b = b + a := by
  omega
  4. 观察现象：
    • 代码行号旁会出现绿色对勾 ✓。
    • 如果右侧没有面板，按 Ctrl+Shift+P 输入 Lean 4: Show InfoView 打开交互面板。
    • 展开面板中的 All Messages，你会看到 1+1 的结果 2，以及 factorial 5 的结果 120。

九、依赖结构（心里有数）

只 require mathlib，Lake 会自动拉入约 9 个包：mathlib 本体 + batteries、Qq、aesop、proofwidgets、LeanSearchClient、importGraph、plausible、Cli。你不需要手动安装或单独编译它们。

十、磁盘占用与精简

  • 全量编译后体积较大，日常学习只需其中一部分（主要是 .olean / .ilean 产物 + .lean 源码）。
  • 安全可删（不影响写证明）：
    • .lake/build/ir（.c / .o 中间文件，不编译可执行文件就没用）
    • 各依赖包 .lake/packages/*/.git（git 历史，不打算 lake update 就没用）
    • 下载缓存目录（如 ~/.cache/mathlib、~/.cache/lean）
  • 绝对别删：
    • .lake/build/lib 里的 .olean / .ilean（mathlib 本体产物）
    • .lean 源码（删了无法跳转定义 / 看源码，学习体验大损）
    • lean-toolchain / lakefile.toml / lake-manifest.json（配置文件）
  • 删完跑一次 lake build 验证秒过、且能跳转源码即成功。代价仅是以后不能 lake update，锁版本学习无影响。

十一、常见问题排查（FAQ）

  • Q: 提示 glean.exe 有木马病毒？
    A: 这是 360 等杀毒软件的启发式误报。`glean` 是交大开源工具，如果不放心，请直接忽略，使用本攻略中手动下载 elan 包的方法。
  • Q: 命令行提示 'elan' 不是内部或外部命令？
    A: 说明 Path 环境变量没生效。请彻底关闭所有命令行和 VS Code，重新打开再试。或者检查 Path 里是否漏了 %ELAN_HOME%\bin。
  • Q: VS Code 右下角一直转圈，或者显示连接失败？
    A: 按 Ctrl+Shift+U 打开输出面板，在下拉菜单选择 Lean 4，查看具体的报错信息。如果是环境变量问题，尝试完全重启 VS Code（确保任务管理器中无残留进程）。
  • Q: lake build 一直拉 GitHub 卡住？
    A: 无代理连不上，改用本地 path 复用，别干等。
  • Q: remote URL changed 后卡死？
    A: 镜像规则失效 + 缓存走 curl 救不了，放弃拉缓存。
  • Q: failed to open ... .olean: 2？
    A: 并发跑 cache + build 弄坏产物。lake build batteries 补，再 lake build。
  • Q: toolchain mismatch？
    A: 两份 lean-toolchain 不一致，对齐 toolchain 即可。
  • Q: 编译中断？
    A: 正常现象，重跑 lake build，勿 lake clean。
  • Q: 想换版本？
    A: .olean 绑定编译器，必须同步换 mathlib，旧产物全废。
  • Q: 想租远程机器编译再下载？
    A: 原理可行（同官方缓存），但远程 toolchain 必须逐字一致、平台尽量相同；如果已在本机编了大半时，不如直接跑完。

十二、一句话总结

无代理环境下，别跟 GitHub / Azure 较劲。锁定一个稳定版本，用 `lake override set` 或 path 依赖指向本机已编译好的 mathlib，对齐 toolchain 后 lake build 即可；编完删 ir 和依赖 .git 做精简。能跑就别更新、别 clean、别并发拉缓存。
